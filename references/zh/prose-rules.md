# 正文规则（Yomiyasu 风格）

适用：长段落、解释性正文。规则语言无关，示例用 EN / ZH 双语给出。

## 1. 保持含义（最高优先级）

改写前后保持以下 4 点不变：

1. **主张**：在说什么。不把论点从一概念滑向另一概念（不把"核心问题"换成"目标"）。
2. **轻重**：什么最重要、什么被轻放。不降级否定项，不重排序。
3. **断言强度**：确定 vs 可能。"may fail" 不写成 "fails"，也不把 "fails" 弱化成 "may fail"。
4. **句子功用**：说明 / 建议 / 规则 / 计划 / 评价。说明不变成指令（"the cache refreshes" ≠ "refresh the cache"），建议不升级为规则。

## 2. 不添加、不删除

- 不添加源文没有的主体、原因、数值、例子、术语、限定。
- 不删除条件、范围、数值、例外、安全限定。
- 信息不足、句子无法确定时，显式标出缺口（如 "（owner TBD）"、"（待确认：重试上限）"），并列出待确认项。不猜测。

## 3. 句子结构

- 每句有可追溯的主语和谓语：谁/什么 对 什么 做 什么。
- 一句话一个意思。
- 拆分长句仅限：前后连接关系（原因、顺序、对比）能用后句的连接词承接时。目的/理由挂在句末从句的句子不拆（拆了"为了什么"会反转）。
- 连接词（因此、但是、另外、so、however、in addition）必须指向一个具体关系。关系不明时不猜，标出待确认。
- 代词（这、那、this、that、the former）只在指代唯一时保留，否则回写名词。
- 无空预告句（"下面有三点："、"Here are three points."）。预告若有分量，并入内容句；没有则删。
- 句长（编辑参考值）：EN 平均 12–25 词；ZH 平均 20–40 字。不为了长度拆句。
- 名词修饰链 ≤3 个名词。"fuel pump valve" 可；"high pressure fuel pump inlet valve assembly" 拆成独立句或改用介词短语。

## 4. 一段话一个话题

- 一段只承载一个话题。
- 不同话题的段落不合并；话题混在一起的段落在不改变句序的前提下拆分。

## 5. 无比喻、无拟人

- 比喻动词换成范围相同的平常词，保留原词的含意（后悔、勉强、低调）。
  - EN: "the data quietly rots" → "the data becomes inconsistent without a log entry"
  - EN: "dive into the code" → "look at the code in detail"
  - ZH: "数据在悄悄腐坏" → "数据在没有任何提示的情况下出错"
  - ZH: "把问题逐个锤掉" → "把问题逐个修掉"
- 不赋予工具、代码、系统情感或意志（"the compiler complains"、"数据在偷懒"）。客观陈述可以："the compiler reports an error"、"编译器报错"。
- 比喻规则只针对比喻义；字面义保留（"the glass breaks"、"玻璃碎了"）。
- 语言中自然、非 AI 味的惯用表达保留。判断标准：AI 普及前的普通文章里也常见，就保留。

## 6. 无自我标注、无填充

- 删除不承担意义的开头："重要的是"、"值得注意"、"总而言之"、"It's important to note that"、"The key point is"、"In conclusion"。
- 例外：开头本身承载评价时，把评价移到谓语保留（"重要的是 X" → "X 是关键"）。
- 否定对比（"不是 A，是 B"）：去掉否定主张不变才改肯定句；否定用于纠正易误读时保留。
- 技术文档不用收尾号召（"Hope this helps!"、"欢迎试用"、"以上就是全部内容"）。

## 7. 装饰

- 无 emoji。
- 无装饰性冒号（标题或句子末尾的装饰冒号）。标签-值冒号保留（"目标：门户"、"date: 10:00"）。
- 严禁使用长破折号。必须使用连接符时，改用普通连字符（-）；也可按语义改用句号、逗号或另起一句。
- 加粗：每 1000 字 ≤1–2 处，只用于读者必须记住的术语。
- 加粗只作渲染：句末标点放在加粗外；`**` 紧贴 CJK 引号或标点导致渲染失败时，在 `**` 外加一个空格（该空格属渲染所需，不视为多余空白）。
- 列表：正文文档中列表占比 ≤15%。列表用于真正的列表，不用来切句子。
- 删除只重复上下文含义的补充括号。
- 保持文档原有语体（正式/中性），不混用语气。

## 8. 立场一致

先判断文档立场，再让每句匹配：

- **建议**（读者应该行动）："you should ..."、"建议…"
- **规则**（读者必须遵守）："the system requires ..."、"必须…"
- **说明**（事实与行为）："the system does ..."、"系统会…"

同一立场内保留强度差异（should / must / may），不升级义务，不弱化必需步骤。

## 9. 语言特定 AI 腔词表

### 英文（避免）

- 动词：delve、harness（营销义）、"under the hood"、"at its core"
- 短语："it's worth noting"、"seamless"、"robust"、"powerful"、"cutting-edge"、"game-changer"
- 套路："the crux of the matter"、"a deep dive"、"elevate"（非事实义）、"streamline"（无具体所指时）

### 中文（避免）

- 黑话：赋能、抓手、底层逻辑、闭环、颗粒度（非技术义）、心智、拉齐、沉淀、打法、组合拳、链路（非网络义）
- 套路：至关重要（开头）、不言而喻、毋庸置疑、一劳永逸、悄悄/悄然（比喻义）、静默（比喻义）

以上词汇在文档中是已定义术语时保留。

- **大词角色名**：把规则叫"契约"、把参照文档叫"正本" → 换成与角色相符的平常词（规则、方针、原文、比较基准）。字面义或已定义术语保留。
- **看似具体的模糊词**："本质"、"手感"、"vibe"、"决策 OS" 类 → 回源文确认指代；是已定义术语或本文话题时保留，否则标出待确认。

## 10. 口号式片段与节奏

- 技术散文不用口号式短片段："For the team. For everyone."、"更稳。更快。"。源文有口号时改写为完整句，保留含义，不删句。
- 不把完整句过度拆成连续超短句。
- 连续 3 句以上结尾或句式相同时才调整，且仅在修 AI 腔时；自然句不为了变化而改结尾。
